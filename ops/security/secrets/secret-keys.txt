# Variables de entorno que son SECRETO de produccion: credenciales, llaves de cifrado y
# tokens. Es la lista canonica que usan los scripts de este directorio y el guardarrail
# de CI. Una variable listada aqui no puede vivir en un fichero del repositorio ni en el
# .env del servidor: su fuente es el almacen de secretos.
#
# Anadir una variable nueva a este fichero es parte de introducir el secreto, no un paso
# posterior: sin ella, fetch-secrets.sh no la materializa y el servicio arranca sin credencial.
#
# Una linea por variable. Se ignoran comentarios y lineas vacias.
#
# Un sufijo "?" marca la variable como OPCIONAL: se materializa si esta en el almacen, pero
# su ausencia no impide publicar el resto. Es para integraciones que aun no se contratan.
# El guardarrail de CI trata igual a las opcionales: opcional no significa publicable.

# Plataforma
# Clave privada Ed25519 con la que identity firma el token de acceso (PKCS#8 DER en base64,
# la genera ops/security/jwt-keygen.sh). La recibe SOLO identity: docker-compose.yml la
# vacia en los demas servicios y check-secrets.sh lo comprueba. Su kid (JWT_SIGNING_KID) y
# las claves publicas (JWT_PUBLIC_KEYS) son configuracion no secreta del .env.
JWT_SIGNING_KEY
INTERNAL_GATEWAY_TOKEN
INTERNAL_SERVICE_TOKEN

# Persistencia
#
# Las credenciales de BASE DE DATOS (POSTGRES_PASSWORD, CELL_DB_PASSWORD, MAIL_DB_PASSWORD,
# el enrutado y una por servicio de empresa) NO estan en esta lista: viven en
# secret-keys-db.txt y se materializan en un fichero aparte que ningun contenedor recibe por
# env_file. Un secreto de este fichero lo ve TODO servicio que lo declare, y eso es
# justamente lo que una credencial de base no puede permitirse.
REDIS_PASSWORD

# Motores de correo: la contrasena de Redis que comparten Rspamd y Dovecot.
MAIL_REDIS_PASSWORD
# Usuario maestro de Dovecot con el que el webmail entra en nombre de cada buzon: la misma
# credencial en los dos lados (DOVECOT_MASTER_* en Dovecot, WEBMAIL_MASTER_* en el webmail,
# con WEBMAIL_MASTER_USER = DOVECOT_MASTER_USER@platform.local). Abre cualquier buzon de la
# celda. Opcionales: una celda sin webmail no las necesita.
DOVECOT_MASTER_USER?
DOVECOT_MASTER_PASS?
WEBMAIL_MASTER_USER?
WEBMAIL_MASTER_PASSWORD?
# Clave del API HTTP de doveadm de la celda (deploy/mail/README.md, "Revocacion en Dovecot"): la
# misma en Dovecot y en mail-security, que vacia por ella la cache de autenticacion de un buzon y
# cierra sus sesiones. De 32 a 256 caracteres de [A-Za-z0-9_-] (openssl rand -hex 32).
# Obligatoria: sin ella mail-security no arranca fuera de development y test.
DOVEADM_API_KEY
# Clave del agente de la cola de Postfix (deploy/mail/README.md, "Gestor de cola"): la misma en Postfix y
# en mail-security. De 32 a 256 caracteres de [A-Za-z0-9_-] (openssl rand -hex 32). Opcional: sin ella el
# agente no abre el puerto y mail-security deja el gestor de cola desactivado (503 NOT_CONFIGURED).
QUEUE_AGENT_API_KEY?
# Migracion de buzones (docs/adr/0002): clave con la que el ejecutor mail-migration-runner pide trabajo a
# mail-migration, la misma en los dos. De 32 a 256 caracteres de [A-Za-z0-9_-] (openssl rand -hex 32).
# Opcional: sin ella el ejecutor no reclama nada y mail-migration responde 503 NOT_CONFIGURED al crear.
MAIL_MIGRATION_RUNNER_KEY?
# Usuario maestro de Dovecot PROPIO de la migracion (distinto del del webmail, para poder rotarlo y acotarlo
# por separado): la misma credencial en Dovecot (DOVECOT_MIGRATION_MASTER_*) y en el ejecutor. Abre cualquier
# buzon de la celda solo desde DOVECOT_MIGRATION_MASTER_ALLOWED_NETS, la red del ejecutor. Opcionales.
DOVECOT_MIGRATION_MASTER_USER?
DOVECOT_MIGRATION_MASTER_PASS?

# Cifrado por dominio (credenciales de terceros guardadas por empresa: relayhosts,
# claves DKIM, credenciales SES propias). Cargada y OBLIGATORIA: lo que se cifre con ella
# queda ilegible el dia que se cambie, por eso no se rellena con un valor improvisado.
MAIL_ENCRYPTION_KEY
# Llaves retiradas, separadas por coma: solo descifran mientras el servicio re-cifra lo
# guardado. Se cargan y se vacian con rotate-key.sh.
MAIL_ENCRYPTION_KEYS_OLD?

# Firma de los enlaces de baja de suscripcion y de seguimiento (HMAC). Independiente del
# token del gateway a proposito: rotar uno no debe invalidar el otro.
MAIL_LINK_SIGNING_KEY

# Amazon SES de la plataforma. Vacias cuando el host autentica por rol IAM.
SES_ACCESS_KEY_ID?
SES_SECRET_ACCESS_KEY?
