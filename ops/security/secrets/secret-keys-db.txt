# Credenciales de BASE DE DATOS. Son secretos de produccion igual que los de
# secret-keys.txt, y se publican en el mismo almacen, pero se materializan en un fichero
# APARTE (secrets-db.env) que NINGUN contenedor recibe por env_file.
#
# Por que separadas: Compose entrega el fichero de secretos entero a cada servicio que lo
# declara en env_file, asi que una credencial de base que viva ahi la ve TODO el
# despliegue: un servicio de celda veia POSTGRES_PASSWORD y uno de empresa
# CELL_DB_PASSWORD. Vaciarlas una a una en los demas servicios crece con el cuadrado del
# numero de servicios y se olvida. Desde este fichero, la credencial solo llega al
# contenedor al que su bloque de docker-compose.yml se la pasa por `environment:`, que
# Compose interpola contra el entorno del proceso (ops/security/secrets/with-secrets.sh).
#
# Quien recibe cada una lo declara ops/db/service-credentials.json y lo comprueba
# ops/scaffold/check-db-credentials.sh.
#
# Mismo formato que secret-keys.txt: una variable por linea, "?" al final = opcional (se
# materializa si esta en el almacen; su ausencia no bloquea el despliegue). Opcional no
# significa publicable: el guardarrail de CI trata igual a las dos.

# Credencial de plataforma: duena de las bases, crea y migra. La reciben solo los servicios
# de plano "registry" (identity, access-control, organization, billing) y los trabajos de
# ops/ que corren fuera de un contenedor (ops/db/pg-credentials.sh).
