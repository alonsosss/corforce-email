# Variables de entorno que son SECRETO de produccion: credenciales, llaves de cifrado y
# tokens. Es la lista canonica que usan los scripts de este directorio y el guardarrail
# de CI. Una variable listada aqui no puede vivir en un fichero del repositorio ni en el
# .env del servidor: su fuente es el almacen de secretos.
#
# Anadir una variable nueva a este fichero es parte de introducir el secreto, no un paso
# posterior: sin ella, fetch-secrets.sh no la materializa y el servicio arranca sin credencial.
#
# Una linea por variable. Se ignoran comentarios y lineas vacias.
#
# Un sufijo "?" marca la variable como OPCIONAL: se materializa si esta en el almacen, pero
# su ausencia no impide publicar el resto. Es para integraciones que aun no se contratan.
# El guardarrail de CI trata igual a las opcionales: opcional no significa publicable.

# Plataforma
JWT_SECRET
INTERNAL_GATEWAY_TOKEN
INTERNAL_SERVICE_TOKEN

# Persistencia
POSTGRES_PASSWORD
REDIS_PASSWORD

# Motores de correo: el rol de solo lectura con el que Postfix y Dovecot consultan el
# directorio de la celda, y la contrasena de Redis que comparten Rspamd y Dovecot.
MAIL_DB_PASSWORD
MAIL_REDIS_PASSWORD

# Cifrado por dominio (credenciales de terceros guardadas por empresa: relayhosts,
# claves DKIM, credenciales SES propias). Cargada y OBLIGATORIA: lo que se cifre con ella
# queda ilegible el dia que se cambie, por eso no se rellena con un valor improvisado.
MAIL_ENCRYPTION_KEY
# Llaves retiradas, separadas por coma: solo descifran mientras el servicio re-cifra lo
# guardado. Se cargan y se vacian con rotate-key.sh.
MAIL_ENCRYPTION_KEYS_OLD?

# Firma de los enlaces de baja de suscripcion y de seguimiento (HMAC). Independiente del
# token del gateway a proposito: rotar uno no debe invalidar el otro.
MAIL_LINK_SIGNING_KEY

# Amazon SES de la plataforma. Vacias cuando el host autentica por rol IAM.
SES_ACCESS_KEY_ID?
SES_SECRET_ACCESS_KEY?

# Observabilidad
GRAFANA_ADMIN_PASSWORD
